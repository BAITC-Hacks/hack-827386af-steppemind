# Предварительная архитектура

Это предложение для первого каркаса, не требование к стеку. Фреймворки, база данных и AI-провайдер пока не выбраны.

## Логические модули

| Модуль | Ответственность |
| --- | --- |
| Конструктор задачи | Черновик, ответы на вопросы, редактирование, подтверждение |
| AI-помощник | Анализ пропусков, уточняющие вопросы, структурирование известных фактов |
| Рейтинг | Детерминированный расчёт, расшифровка, уровень готовности |
| Каталог | Публикация, сортировка, фильтры, просмотр |
| Команды и отклики | Профиль команды, предложение, решение бизнеса |
| Хранение | Сохранение карточек, подтверждений, команд и откликов |

Для MVP модули могут жить в одном приложении. Отдельные сервисы не требуются.

## Сущности

| Сущность | Основные поля |
| --- | --- |
| Task | id, businessId, исходное описание, тема, название, контекст, потребность, пользователи, данные, ограничения, результат, критерии успеха, контакт, формат взаимодействия, статус публикации, версия |
| Confirmation | taskId, версия карточки, подтверждённые поля, время подтверждения |
| Rating | taskId, версия карточки, итог, баллы по критериям, недостающие сведения, уровень |
| Team | id, название, интересы, навыки, технологии |
| Proposal | id, taskId, teamId, идея, план, срок, ссылка на прототип, решение |

Предлагаемые статусы публикации: `draft`, `published`; решения по отклику: `pending`, `accepted`, `rejected`. Готовность хранится отдельно от публикации.

## Правила переходов

1. AI-результат всегда поступает в редактируемый черновик.
2. Подтверждение связано с версией текста: правка требует нового подтверждения изменённых сведений.
3. В каталог попадает подтверждённая версия; неподтверждённые правки не заменяют публичный текст.
4. Рейтинг соответствует той же версии, что и опубликованная карточка.
5. Отклик доступен на любую опубликованную задачу независимо от рейтинга.
6. Только бизнес-владелец принимает решение по своим откликам; несколько принятых предложений допустимы.

## Граница AI

Предлагаемый вход: исходное описание, известные поля и ответы бизнеса.

Предлагаемый выход: недостающие поля, минимум 3 уточняющих вопроса на этапе уточнения и предложенные значения карточки. Неизвестное остаётся пустым, а не заполняется догадками.

До применения ответа проверять структуру, типы полей и наличие вопросов. Некорректный ответ или недоступный провайдер не должны удалять введённые данные. Локальную заглушку явно обозначать в интерфейсе. Расчёт баллов выполнять отдельно от генерации текста.

## Решения после первого каркаса

- Стек интерфейса и приложения.
- Хранение и восстановление данных после перезапуска.
- AI-провайдер либо демонстрационная заглушка.
- Проверка достаточности сведений для начисления баллов.
- Способ переключения демонстрационных ролей бизнеса и команды.
