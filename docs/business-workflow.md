# Бизнес-конструктор: реализованный сценарий

Мастер доступен бизнес-аккаунту через «Создать задачу». Пять шагов: свободное описание → уточнение → редактируемая карточка → подтверждённая готовность → явная публикация. Сохранённые задачи доступны в списке над мастером.

## Подтверждение и публикация

AI-анализ создаёт только черновик. «Сохранить черновик» сохраняет правки без подтверждения. «Подтвердить сведения задачи» подтверждает текущую версию и рассчитывает официальный рейтинг. «Перейти к публикации» открывает просмотр перед отдельным действием «Опубликовать задачу».

Изменение любого поля снимает подтверждение текущей версии. Повторное подтверждение пересчитывает весь рейтинг, расшифровку, пропуски и рекомендации; показывается предыдущий и новый балл. Для уже опубликованной задачи студенты продолжают видеть предыдущую публикацию до явной повторной публикации. ID задачи и её отклики сохраняются.

Отсутствующие поля видны и остаются пустыми. Низкий рейтинг, включая 0/100, не препятствует публикации или откликам. Для публикации требуется название минимум из трёх символов; отрасль необязательна.

## Формула

| Категория | Баллы |
| --- | ---: |
| Контекст и потребность — оба поля | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт и формат взаимодействия — оба поля | 10 |

Категория начисляется полностью, если её поля заполнены и карточка подтверждена. Пробелы не считаются заполнением; короткий ответ, например «HR», допустим. Это оценка полноты подтверждённого описания, а не автоматическая проверка качества или достоверности обещаний бизнеса.

Уровни: 0–39 — черновик, 40–69 — рабочая, 70–89 — готовая, 90–100 — приоритетная. Уровень «Черновик» обозначает готовность и не означает, что опубликованная задача скрыта.

## AI и локальный режим

С ключом используется OpenAI Responses API со Structured Outputs. Непустые извлечённые значения должны быть дословными фрагментами исходного текста; сервер отбрасывает значения, которых в тексте нет. Это ограничивает выдуманные факты, но правильность классификации всё равно проверяет бизнес.

Без ключа, при ошибке или тайм-ауте работает консервативный локальный разбор. Он распознаёт явные формулировки и строки «Users: …», «Данные: …» и аналогичные, но не обладает пониманием произвольного текста на уровне модели. Интерфейс явно отмечает локальный режим. Контакты, сроки, данные и KPI автоматически не дополняются.

Вопросы выбираются по отсутствующим полям: 3–5 вопросов, без повторного запроса уже заполненных полей. Если осталось одно-два отсутствующих поля, задаются разные уточнения по ним. Если все обязательные поля уже указаны, повторные вопросы не создаются, открывается проверка карточки. Ответы переносятся в соответствующие редактируемые поля без выдуманных дополнений.

## Общая база и API

Единственный источник задач — таблица `tasks` в SQLite. Последняя опубликованная карточка и приватная рабочая копия хранятся в одной строке. Миграция добавляет поля версий и не удаляет существующие задачи. Для старых опубликованных задач инициализируется подтверждение и пересчитывается рейтинг по общей формуле; владелец не назначается автоматически.

- `GET /api/tasks`: собственные рабочие копии, только бизнес.
- `POST /api/tasks`, `action: "save"`: `{card, description, language, id?, version?}`. Возвращает `{task}`. При изменении нужны ID и актуальная версия.
- `POST /api/tasks`, `action: "confirm"`: `{id, version, confirmed: true}`.
- `POST /api/tasks`, `action: "publish"`: `{id, version}`. Требует подтверждения именно этой версии.
- `GET /api/state`: общий каталог опубликованных задач с `id`, карточкой, `industry`, `score`, `readinessLevel`, `status`. Приватные правки и метаданные подтверждения не выдаются.

Ошибки: 401 — нет сессии, 403 — неподходящая роль, 404 — нет собственной задачи, 409 — устаревшая версия или отсутствует подтверждение. Проверки версии и запись выполняются в транзакции. В случае конфликта версии обновите страницу и откройте сохранённую задачу заново.

Совместимость: старое действие `POST /api/state` → `createTask` теперь сохраняет **черновик** и возвращает его в `draft`; оно больше не публикует задачу в обход подтверждения. Для публикации используйте новый последовательный API. Контракты откликов сохранены.

Общий существующий каталог поддерживает сортировку по баллам в обе стороны и фильтры по отрасли и уровню готовности.

## Демонстрация 45 → 80

1. Войти как бизнес и открыть «Создать задачу».
2. Ввести: `We have high employee turnover and want to use our HR data to identify employees at risk of leaving.`
3. Проанализировать: увидеть известные и отсутствующие поля и 3–5 вопросов. Ответить о пользователях: «HR», о результате: «Отчёт с рисками ухода». Остальное можно пропустить.
4. Собрать карточку. Указать название «Анализ текучести персонала» и отрасль «HR». Для демонстрации ровно 45 баллов очистить данные: на этом этапе их доступность ещё не подтверждена. Оставить контекст, потребность, пользователей и результат. Критерии, ограничения, контакт и формат связи оставить пустыми.
5. Подтвердить сведения: 45/100, рабочая. Посмотреть пропуски и рекомендации +20 за данные, +15 за критерии, +10 за ограничения, +10 за коммуникацию.
6. «Дополнить карточку»: указать данные «Анонимизированный CSV с историей сотрудников» и критерий «Recall не ниже 80% на отложенной выборке». Это вводимые бизнесом примеры для демонстрации, не AI-догадки.
7. Подтвердить повторно: 45 → 80, готовая. Расшифровка и рекомендации обновляются.
8. Перейти к публикации и нажать «Опубликовать задачу». Увидеть уведомление и ID.
9. Открыть каталог; затем войти студентом. Та же задача видна с тем же рейтингом и полной карточкой. Проверить фильтры «HR», «Готовая» и сортировку.

## Проверки

`npm run lint`, `npm run test:logic`, `npm run build`, затем `npm run test:auth`.

Проверки логики охватывают 128 сочетаний категорий, границы уровней, отбрасывание выдуманных значений и релевантность вопросов. HTTP-тест использует отдельную временную SQLite-базу: роли и владельцы, черновик → подтверждение → публикация, 45 → 80, устаревшие версии, приватность правок, 0 баллов, повторная публикация без дубликата, AI fallback и сохранение после перезапуска.
